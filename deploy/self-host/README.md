# Self-hosted OHSMS (this machine only)

This package runs one company on the computer it is unpacked on. It is not
the shared WEEHS suite and it does not talk to Firebase. Postgres, Keycloak,
and MinIO are real services with named volumes. The app host serves the
built SPA and stores files in MinIO.

Ports are published on `127.0.0.1` only. Do not add a tunnel, change DNS, or
publish these ports on another interface.

## Prerequisites

- Apple Silicon or another arm64 machine, or amd64 (the pinned images are
  multi-arch)
- Docker Desktop with Compose v2
- Node.js 22, used once to generate secret files
- Network access the first time MinIO is built, so the official Go image,
  Debian image, and `github.com/minio/minio` tag
  `RELEASE.2025-10-15T17-29-55Z` can be fetched. Do not use `docker login`
  for MinIO. Docker Hub repository `minio/minio` returns 404 (it is gone,
  not private). `quay.io/minio/minio` returns 401 to an anonymous pull.
  This package does not log in and does not use a third-party fork.
- No host Postgres is required

## Secret file contract

Create the directory and the one password you will type at the Keycloak
login. Choose it yourself. Do not copy a password out of this document.

```sh
mkdir -p secrets
umask 077
touch secrets/bootstrap-password
chmod 600 secrets/bootstrap-password
```

`secrets/bootstrap-password` is mode `0600`, one line, at least 12
characters, no quotes. That line is the password for the person named as
the contact email on the registration form. It is also the only password
you type. Service passwords are generated by the next command and are not
printed.

```sh
node bootstrap.mjs
```

That writes, and will not overwrite if you run it again:

| File | What it is |
| --- | --- |
| `secrets/postgres-password` | Postgres role `ohsms` |
| `secrets/minio-root-password` | MinIO root password. The user name is `ohsms` |
| `secrets/keycloak-admin-password` | Keycloak admin console (`admin`) |
| `secrets/session-secret` | Signs the app session |
| `secrets/data-key-master` | This company's data-key master |
| `secrets/control-token` | Operator token. The browser does not receive it |
| `secrets/compose.env` | The three service passwords, for Compose |

Do not `cat`, log, or commit these files. `docker compose config` prints
them. Do not paste that output anywhere.

## Start, status, stop

Building MinIO does not rebuild the app. From this directory, after
`node bootstrap.mjs`:

```sh
docker compose build minio
docker compose up -d --no-build
docker compose ps
docker compose stop
```

`--no-build` keeps the existing app image. `build minio` only compiles
MinIO from the public Git tag. `stop` does not delete volumes. Start again
with `docker compose up -d --no-build`. Do not run `docker compose down -v`.

A first install that has not built the app yet uses `docker compose up -d --build`
once. After that, use `--no-build` as above.

### Rebuild only the app

`stack/presign.mjs` imports `functions/lib` before the process listens. An
image that copied `stack/` and not `functions/` exits with
`ERR_MODULE_NOT_FOUND` and never opens `:8787`. The Dockerfile copies
`app/functions` as well as `app/stack`. `deploy/self-host/runtimeClosure.mjs`
is the file list, and `src/shared/data/selfHostPackage.test.js` imports
`stack/self-host.mjs` from a directory that contains only that list.

When that image is already running and Postgres, MinIO, and Keycloak are
healthy, replace the app container only. Do not replace `docker-compose.yml`,
`minio/`, or `secrets/`. Do not run `docker compose down` or `down -v`.

```sh
docker compose ps -q postgres minio keycloak
docker compose build ohsms
docker compose up -d --no-deps --force-recreate ohsms
docker compose ps -q postgres minio keycloak
curl -fsS http://127.0.0.1:8787/health
```

The two `ps -q` lines should print the same three container ids. `build ohsms`
does not rebuild MinIO. `--no-deps` does not recreate Postgres, Keycloak, or
MinIO. Named volumes `pgdata` and `miniodata` stay.

### Health

Postgres: `pg_isready` inside `postgres:16-alpine`. That image contains it.

MinIO: `curl -fsS http://127.0.0.1:9000/minio/health/live` inside the image
this package builds. The documented probe is `/minio/health/live`.
`mc ready local` belongs to the removed `minio/minio` image, which bundled
`mc`. This source build does not, so that check is not used.

Keycloak `26.0.7` is `ubi9-micro` plus Java, a glibc langpack, and findutils.
It does not include curl. The old in-container `/dev/tcp` check is not used.
Health is enabled with `--health-enabled=true` and published only on
`127.0.0.1:9002`. From the host, after start:

```sh
curl -fsS http://127.0.0.1:9002/health/ready
```

The documented body has `"status":"UP"`. These checks were not executed
here. Docker is not available in the environment that prepared this file.

## URLs (this machine)

| | |
| --- | --- |
| App | http://127.0.0.1:8787 |
| Register | http://127.0.0.1:8787/register-org |
| Keycloak (IdP and its admin console) | http://127.0.0.1:8080 |
| Keycloak health | http://127.0.0.1:9002/health/ready |
| MinIO API | http://127.0.0.1:9000 |
| MinIO console | http://127.0.0.1:9001 |
| Postgres | 127.0.0.1:5432, database `ohsms`, user `ohsms` |

The registration form is filled with the running issuer
`http://127.0.0.1:8080/realms/ohsms`, client id `ohsms`, bucket `ohsms`,
and presign `http://127.0.0.1:8787/presign`. Those are the services this
compose file started. The IdP certificate and the database URL stay on the
server. The form does not ask for them.

## Register and sign in

1. Open http://127.0.0.1:8787/register-org and choose your own database.
2. Confirm the issuer, client id, bucket, and presign URL already shown.
   They must be the loopback addresses above.
3. Use a real contact email. That email becomes the Keycloak user. The
   password is the line in `secrets/bootstrap-password`.
4. Submit. The host fulfills against its own Postgres. The page shows
   http://127.0.0.1:8787 when the organization is live.
5. Sign in. The browser goes to Keycloak. The app session is not enough
   for a second visit: sign-out sends a SAML logout to Keycloak and the
   next sign-in sets `ForceAuthn`, so Keycloak asks again.

## Check persistence

```sh
docker compose stop
docker compose up -d
```

Sign in again. The organization, its records, and an uploaded file are
still there. MinIO and Postgres use named volumes `miniodata` and `pgdata`.

## What this package does not do

Docker is not available where this file was written, so none of these
containers were started here. If a service fails, `docker compose logs
<service>` is the next step. The app retries Postgres, MinIO, and Keycloak
for about three minutes and does not print passwords when a retry fails.
There is no public hostname until you choose one yourself. Do not point
this stack at the shared Firebase project.
